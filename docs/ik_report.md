# arm01 inverse kinematics: solvers and benchmark

Generated by `tools/ik_benchmark.py` (2000 targets, seed 0, 95 s). Solvers: `arm_stack/model/ik.py`; model: `urdf/arm01/arm01.urdf`, tool frame `tool0`. Python 3.10, numpy 1.21.5, Pinocchio 4.0.0, single thread. FK 2.6 us, FK+Jacobian 3.8 us per call.

Success = position error < 0.1 mm and rotation error < 0.1 deg. Targets: FK of uniform random configurations inside the joint limits, so every target is reachable. Seeds: **nominal** = mid-range posture; **near** = truth + U(+-0.1 rad) per joint (tracking-like). Failure classes (final iterate): *limit* = a joint at a stop, *singular* = sigma_min(J) < 1e-3, *local_min* = neither, *max_iters* = iteration cap.

Every result of every solver was inside the joint limits: yes.

## Solvers

| name | method |
|---|---|
| dls | damped least squares on the log6 twist error, Nakamura manipulability damping, clamp to limits |
| lm | Levenberg-Marquardt, damping lam*E + 1e-6 (Sugihara), accept/reject, projection + active set |
| clik | weighted-least-norm CLIK (Chan-Dubey limit weights), null space: rest posture (mid-range) + limit barrier; active set |
| multistart-lm | lm from the seed, then up to 40 random restarts in the limits, first feasible |
| multistart-clik | the same with clik (solutions keep the posture objective) |

## Continuous tracking

Closed path: FK of a periodic joint trajectory (mid-range +- 30% of half-range, harmonics 1-3), 1000 steps per loop at 100 Hz, 4 loops, each step seeded with the previous solution. jump = a step with max |dq| > 0.05 rad (5 rad/s). For the same tool pose (loop start): the joint change over each loop (max abs) and the elbow displacement. The first loop includes any transient toward the rest posture; later loops show drift that keeps accumulating (0 = cyclic).

## Findings

- From the nominal seed the single-shot solvers reach dls 76.1%, lm 86.9%, clik 74.8% of the targets. Almost all failures end with a joint at a stop: the solution lies across a joint limit from the seed (J1..J7 ROM, above all J6 +-35 deg), a local minimum that gradient methods cannot leave. Restarts fix it: multistart-lm 100.0%, multistart-clik 99.9%.
- From a near seed (tracking) all solvers converge in a few iterations: dls 99.7% (0.28 ms median), lm 100.0% (0.16 ms median), clik 99.4% (0.50 ms median).
- Tracking: plain pseudo-inverse solvers (dls, lm) have no preference in the null space, so the posture is not cyclic: each loop of the same closed tool path leaves the joints 0.91 deg (dls) / 0.91 deg (lm) further away (elbow 1.2 / 1.2 mm per loop), without bound. CLIK with the rest-posture term moves toward rest during the first loop (21.1 deg) and is then cyclic (0.000 deg/loop; IKTracker 0.000 deg/loop).

## Recommendation

- **Teleop / task-space control:** `IKTracker(model, q_now, dt, method='clik')` (defaults: max_iters 30, min_iters 1, k_rest 0.05 toward mid-range, k_limits 0.2, WLN on, ns_step 0.05 rad, joint speed cap min(URDF, 1.5 rad/s)). It is the only option that is both continuous and cyclic.
- **One-shot targets (calibration poses, planning):** `ik.solve(model, T, q_seed, method='multistart', base='clik', n_starts=40)` (add `select='rest'` to prefer the posture nearest mid-range). `base='lm'` is the fastest if posture does not matter.
- `lm` is the fastest local solver (best for many warm-started solves, e.g. batch planning; `solve_batch` is its vectorized form). `dls` is kept as the reference baseline.

## Optional packages

TRAC-IK (trac_ik / tracikpy / trac_ik_python) and pink are not importable in WSL. `pin-pink` and `qpsolvers` are pure Python (~170 kB of wheels), but pink needs a compiled QP backend (quadprog, proxsuite, daqp, osqp: none installed), so it was not installed or benchmarked. pink is a differential (velocity-level QP) IK like `clik` here, with inequality limits instead of WLN weights.
